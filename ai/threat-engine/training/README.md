# MAILTRACE 2.0 — AI Threat Engine Training & Dataset Subsystem

## Overview
This directory houses the dataset provenance catalog, acquisition audit, normalization, deduplication, validation, reporting, and training orchestration pipeline for fine-tuning a RoBERTa sequence classification model on email security threats.

> [!WARNING]
> **No Training Data Currently Present**: This repository does NOT ship with pre-packaged training datasets or synthetic fallback data. A verified, authentic email threat dataset must be acquired, normalized, and validated prior to starting model training. The runner strictly refuses execution if data is absent or if provenance checks fail.

### Authentic Data vs. Generated/Simulated Data

* **AUTHENTIC REAL DATA**:
  * **Enron**: Real historical business emails exchanged between Enron employees released during the FERC investigation.
    * *Mapping Rationale*: `unlabeled legitimate/business corpus -> benign`. **This is a modeling assumption for the MAILTRACE training taxonomy, not an original threat label supplied by Enron**.
  * **SpamAssassin (Ham)**: Real historical user-donated emails.
    * *Mapping Rationale*: `easy_ham -> benign`, `hard_ham -> benign`.
    * *Spam Partition*: `spam -> unresolved`. Commercial bulk spam cannot be safely mapped to phishing or suspicious without specific threat telemetry. Strictly rejected.
  * **Nazario Phishing**: Real-world collected phishing attacks from honeypots between 2004 and 2024. Contains authentic credential lures and deceptive links.
* **GENERATED / SYNTHETIC DATA**:
  * **BEC-2**: Contains **279 samples** generated by an LLM-based system using real-world BEC scenarios as seeds (Rohit Dube, UC Berkeley, October 2024).
    * *Provenance Type*: `generated_from_real_world_bec_examples`.
    * *Strict Rule*: **Never claim or represent BEC-2 as 279 authentic real-world BEC emails**.

## 3. Dataset Count Semantics

The pipeline explicitly distinguishes three levels of sample counts:
1. `source_sample_count`: Approximate or verified samples available from the external source (e.g. ~500,000 for Enron, ~6,047 for SpamAssassin, 279 for BEC-2, or `null` when unverified).
2. `downloaded_count`: Raw samples currently downloaded to local storage (`data/raw/`).
3. `normalized_count`: Clean, deduplicated samples prepared in `data/dataset.csv`.

`null` is used when a source count has not yet been verified. `0` strictly denotes that zero samples have been downloaded or normalized.

## 4. Canonical Label Taxonomy & Mapping Rules

MAILTRACE enforces a strict 4-class multi-class taxonomy:

| Label ID | Canonical Class Name (`label`) | Description |
| :---: | :--- | :--- |
| `0` | `benign` | Legitimate corporate, personal, or administrative communications |
| `1` | `suspicious` | Anomalous headers, graymail, marketing tracking, or unconfirmed indicators |
| `2` | `phishing` | Deceptive links, credential harvesting, brand impersonation |
| `3` | `business_email_compromise` | Executive impersonation, urgent payroll/wire rerouting, vendor invoice fraud |

### Explicit Label Mapping Table

| Source | Original Label | MAILTRACE Label | Status | Rationale |
| :--- | :--- | :--- | :---: | :--- |
| Enron | `unlabeled_corporate_correspondence` | `benign` | Blocked* | Modeling assumption; not natively labeled benign |
| SpamAssassin | `easy_ham` | `benign` | Blocked* | Legitimate non-spam donated email |
| SpamAssassin | `hard_ham` | `benign` | Blocked* | Complex non-spam donated email |
| SpamAssassin | `spam` | *None* | **Rejected** | Commercial bulk spam remains unresolved |
| Nazario | `phishing` | `phishing` | Blocked* | Honeypot credential lures |
| BEC-2 | `bec` | `business_email_compromise` | Blocked* | Generated scenarios; blocked pending license |
| IWSPA | `phishing` / `legitimate` | `phishing` / `benign` | Blocked* | Restricted institutional access |

*\* Blocked until manual legal/licensing verification and raw file acquisition.*

## 6. Training Eligibility Criteria

A dataset source is eligible for training ONLY when ALL of the following criteria are met:
1. Real authoritative source verified
2. Source URL verified (no placeholders)
3. Provenance documented (authentic vs. generated)
4. License / usage permission verified
5. Original labels understood
6. MAILTRACE mapping explicitly justified
7. Raw data successfully acquired
8. Normalization successful into canonical 10-column schema
9. Duplicate processing complete (exact and cross-source)
10. Leakage checks pass across train/val/test splits
